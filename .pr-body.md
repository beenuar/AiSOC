## What this is

Close-out of the v20.1.0 media work. The screenshots themselves were already
re-captured in the release (#1476) and are current — verified by what they
show, not by the commit touching them: footer `v20.1.0`, `Evaluate on History`
and `EASM` present, the removed `Investigation Chat` gone, 1,754 live KEV rows,
a real local-model verdict, alerts labelled `aisoc_sample`.

What was missed is everything downstream of those files.

## The published PDF was still showing the old console

`apps/web/public/papers/aisoc-technical-guide.pdf` — the "26 page PDF" the
README front page advertises — was last rendered in #1229. The release swapped
fifteen captures underneath it and never re-rendered, so the document a reader
downloads showed a console two releases old.

**The check for exactly this passed throughout.** `papers.yml` already triggers
on `apps/web/public/screenshots/**`, with an inline comment explaining why a
screenshot refresh changes the rendered PDF while leaving every other watched
path untouched. The trigger was right; the comparison was blind to it, because
the recorded digest covered only the markdown. The digest is now taken over the
**source closure** — the markdown plus every local figure it embeds, keyed by
path so repointing a caption at a different file counts as a change too.

Evidence it detects the real defect, run on this tree before the re-render:

```
$ python3 scripts/render_white_paper.py --check
[render_white_paper] rendered PDFs are out of date:
  - aisoc-technical-guide.md changed since its PDF was rendered
```

It names the guide and leaves `l0-l4-automation-maturity.md` alone, which
embeds no figures — so its recorded digest is unchanged and its PDF is not
touched by this PR. Two self-test cases cover the new behaviour: the negative
control (a figure re-captured after the render is refused) and the positive
control that stops the gate from refusing everything. 8/8 pass.

## Re-rendering exposed captions describing the previous images

The captures were swapped under captions written for the ones they replaced, so
the guide asserted things its own figures contradicted:

| Caption said | Figure shows |
|---|---|
| "Twelve alerts the pipeline produced" | five alerts |
| "confidence 80/100" | 85/100 |
| "1,725 real Known Exploited Vulnerabilities entries" | 1,754 |
| "The connector catalogue, reporting **84 connector types available**" | the connectors page, nothing connected, no catalogue in frame |
| "The step palette … captured when the vocabulary was twenty-two members" | a nine-step playbook in the editor |

Each is now written against what is actually in the frame. The step-palette
caption's point — that `approval` is offered now that it can durably pause —
survives, because it is visible in the new image as step 6.

## Two assets decided rather than re-captured

- **`attack-graph.png` is stale and stays, dated.** It is a v10.0.0 capture
  (footer `v10.0.0`, and the nav still shows the removed `Investigation Chat`)
  presented as current. The populated graph needs the `full` profile, so rather
  than delete the only recorded one it is now dated in both the guide and the
  provenance README, next to the CORE capture that shows the same page
  degrading honestly. Re-capturing it is a `full`-profile job, not a CORE one.
- **`connectors.png` is deleted.** It duplicated `connector-wizard.png`'s view
  and carried a rendering artifact — a second sidebar bleeding into the right
  edge — which was being shipped inside the PDF. Nothing else referenced it.

**No screenshot was re-captured.** `git diff f2955c7c..origin/main -- apps/web/`
is empty, so the console today is byte-identical to the one already in the
committed images; a re-capture would reproduce the same pixels and risk a worse
set.
