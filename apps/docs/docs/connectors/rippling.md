# Rippling

Employment status, start and end dates, manager, department and worker type from Rippling, as triage context. Read-only; compensation and personal data are never requested.

- **Connector id:** `rippling`
- **Category:** hr

## Configuration

| Field | Label | Type | Required | Default | Notes |
|-------|-------|------|----------|---------|-------|
| `api_token` | API token | secret | yes | — | **encrypted at rest** · A Rippling API token or installed-app access token carrying the workers.read scope. |
| `base_url` | API base URL | string | no | `https://rest.ripplingapis.com` | Override only if Rippling has given you a different regional host. |

:::note Credential handling
`api_token` is encrypted at rest by the credential vault before the row is written, and decrypted only at poll time. The value is never logged and never returned by the API — a read of the saved connector shows the field as set, not its contents. See [credential vault](../operations/credentials.md).
:::

## Capabilities

- `pull_workforce`

## Setup

1. In the console, go to **Connectors → Add connector** and pick **Rippling**.
2. Fill in the fields above and run **Test connection**. The test is read-only and does not save anything.
3. Save. Polling starts on a jittered schedule within about a minute; the connector row shows `last_sync` once the first poll completes.

:::tip If `last_sync` stays empty
The first poll is the honest signal that the credential works. A connector that saves cleanly and never syncs usually means the credential lacks a scope the vendor requires for reads — check the connectors service log for the vendor's own error, which is passed through verbatim rather than summarised.
:::
