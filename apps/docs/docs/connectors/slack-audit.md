# Slack Audit Logs

Slack Enterprise Grid Audit Logs. Pulls workspace and org-level audit events (logins, channel changes, file shares, app installs). Requires the auditlogs:read scope on an Org-level Slack app.

- **Connector id:** `slack_audit`
- **Category:** saas
- **Authentication:** OAuth

## Configuration

| Field | Label | Type | Required | Default | Notes |
|-------|-------|------|----------|---------|-------|
| `access_token` | Org-level access token | secret | yes | — | **encrypted at rest** · OrgLevel OAuth bot token with the auditlogs:read scope, issued from a Slack Enterprise Grid app. |

:::note Credential handling
`access_token` is encrypted at rest by the credential vault before the row is written, and decrypted only at poll time. The value is never logged and never returned by the API — a read of the saved connector shows the field as set, not its contents. See [credential vault](../operations/credentials.md).
:::

## Setup

1. In the console, go to **Connectors → Add connector** and pick **Slack Audit Logs**.
2. Fill in the fields above and run **Test connection**. The test is read-only and does not save anything.
3. Save. Polling starts on a jittered schedule within about a minute; the connector row shows `last_sync` once the first poll completes.

:::tip If `last_sync` stays empty
The first poll is the honest signal that the credential works. A connector that saves cleanly and never syncs usually means the credential lacks a scope the vendor requires for reads — check the connectors service log for the vendor's own error, which is passed through verbatim rather than summarised.
:::
