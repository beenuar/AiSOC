Splunk Enterprise / Cloud notable events via the REST API.

- **Connector id:** `splunk`
- **Category:** siem

## Configuration

| Field | Label | Type | Required | Default | Notes |
|-------|-------|------|----------|---------|-------|
| `base_url` | Splunk URL | string | yes | — | Management port (default 8089), not the web UI port. |
| `token` | HEC / API Token | secret | yes | — | **encrypted at rest** |
| `saved_search` | Saved Search Name | string | no | `AiSOC_Alerts` | Dispatched via the saved-search endpoint. Leave blank to search index=notable. |
| `page_size` | Results page size | number | no | `500` | Number of results fetched per page. Polling pages through all results — there is no 100-event cap. |
| `ssl_verify` | Verify SSL certificate | boolean | no | `True` | Disable only for self-signed certificates in private deployments. |

:::note Credential handling
`token` is encrypted at rest by the credential vault before the row is written, and decrypted only at poll time. The value is never logged and never returned by the API — a read of the saved connector shows the field as set, not its contents. See [credential vault](../operations/credentials.md).
:::

## Setup

1. In the console, go to **Connectors → Add connector** and pick **Splunk SIEM**.
2. Fill in the fields above and run **Test connection**. The test is read-only and does not save anything.
3. Save. Polling starts on a jittered schedule within about a minute; the connector row shows `last_sync` once the first poll completes.

:::tip If `last_sync` stays empty
The first poll is the honest signal that the credential works. A connector that saves cleanly and never syncs usually means the credential lacks a scope the vendor requires for reads — check the connectors service log for the vendor's own error, which is passed through verbatim rather than summarised.
:::
